LUMC Project at the XR Lab

I am doing my internship at the Saxion XR Lab, where I am mostly working on this virtual reality project for the Leiden University Medical Center (LUMC).

The project

This is a VR project for Leids Universitair Medisch Centrum (LUMC). It is a virtual training environment to train anesthesiologists, where they can practice actions like intubation and IV insertion and immediately see the consequences of their success or mistakes. The project has been running for a while and there is already a working prototype made in Unreal Engine, which consists of an Operation Room with a patient, and a few machines, tools and syringes that can be used.

My contribution

I am working on adding interactions and improving the code structure. This project is made in Unreal Engine, which means I am working with blueprints and c++. Below are two examples of things I have worked on.

Yankauer Waste System

I implemented the interactions with the yankauer waste system. This is the system for suctioning liquids from in and around the patients mouth. It consists of a suction tip, waste canister and control panel. The suction tip is the part that is picked up and moved around by the user, so I made this object grippable. The suction tip is connected to the waste canister with a tube, which is a spline that moves with the suction tip when it is moved. The control panel has two dial buttons and a clockface. The suction can be turned on by turning the right dial button of the control panel past a certain angle. The handle of the clockface will then also turn, to indicate that the suction is turned on. I implemented these interations and movements in blueprints.

Patient Subsystem

In the Operation Room several patient-related values (e.g. heartrate) are set by one object, and need to be displayed or updated to other objects in the room. The way this was originally set up was a bit unstructured, as it was not always clear where the values where stored. To clean this up, it would be ideal to have one central hub where all the patient values are stored, which can be accessed by the object in the scene.

A subsystem class should be created as a c++ class that inherits from either the Engine, Editor, GameInstance or Localplayer subsystem class. The subsystem can then be directly accessed by any objects in the level.

In the case of the OR room, a patient subsystem is needed, which will keep track of the heartrate, saturation, upper and lower bloodpressure and breathing values. Any blueprint can then set and get these values directly from the patient subsystem. The c++ class should inherit from GameInstanceSubsystem, because it should have the same lifetime as the GameInstance.
